# Editor Component Architecture

The editor is the primary workspace of HermesMarkdown, located in `app/editor`.

## Core Editor

### `MarkdownEditor`
The app's current editor is built on CodeMirror 6, with the source-mode implementation in `app/editor/codemirror` and the feature overlays in `app/editor/hooks`.
- Synchronizes content with the active file and frontmatter handling for document metadata.
- Supports slash commands, wiki links, date pickers, tables, and workflow/todo pills.
- **Slash menu** (`codemirror/slash-menu.ts`, search and blocks in `codemirror/slash-commands.ts`): `/` at the start of a line or after a space opens a menu of commands. With nothing typed it is grouped into sections (Basic blocks, Insert, Templates, Note, AI); typing searches each command's name, a later word of it, its aliases (`Template.aliases`: `/h1`, `/todo`, `/yaml`, `/url`) and, from three letters, the words of its description, best match first (`rankSlashCommands`). The **Basic blocks** (Text, Heading 1–3, Bulleted / Numbered / To-do list, Quote, Divider) turn the caret's line into that block and keep its text, so `Intro /h2` becomes `## Intro` (`applyBlockCommand`, one undo step, using `block-type.ts`); a divider goes on a line of its own with a blank line above. **Emoji** leaves a `{` and opens the emoji menu.
- **Emoji menu** (`codemirror/emoji-completion.ts`, search in `codemirror/emoji-index.ts`): `{` (or `:` at a word's start with a letter after it, `:fi`) opens a list of every emoji — the curated `EMOJI_SHORTCODES` in `components/constants.ts` (`{fire}`, `{idea}`, …) first, then the full Unicode list by CLDR name (`{thumbs_up}`, `{red_heart}`), the names Emojipedia uses. Typing narrows it: the exact name, names starting with what was typed, a later word of a name (`up` → thumbs_up), a GitHub alias or keyword (`+1`, `flame` → fire), then names containing it. Picking one inserts the emoji, as typing the whole shortcode does. The list (`codemirror/emoji-data.json`, written by `scripts/generate-emoji-data.mjs` from emojibase) loads in its own chunk the first time a menu opens; options are built once and reused, and the menu draws only the 50 around the selection (`maxRenderedOptions`). Not after `{{` (template fields) or in code.
- **Frontmatter menu** (`codemirror/frontmatter-completion.ts`, vocabulary in `utils/frontmatter-vocabulary.ts`): inside the `---` block, a key typed at the start of a line offers the common keys and those the vault uses (minus ones already in the block); picking `tags` or `aliases` inserts `key: []` with the caret inside, picking another key reopens the menu for its values. In `tags: [wo` or a `- wo` item under `tags:` it offers the vault's tags, most used first, minus those in the list; after another key it offers the short values the vault repeats (`status: draft`). Empty values wait for a letter unless the menu was opened (a key pick, Ctrl+Space). The vocabulary comes from `frontmatterVocabulary`, set in `useCodeMirrorTemplates`. Private notes' keys, tags and values are never offered.
- Renders Mermaid fences and display math (`$$ … $$`, ```` ```math ````) in place of their source; double-click one to edit it.
- Inline calculator: math lines show their result at the end of the line (see [Inline calculator](#inline-calculator)).

### File navigation
Vault files are browsed through the command palette (`Ctrl/Cmd+K`) and Files: the Files section of the desktop `WorkspaceSidebar`, or on mobile the full-screen Files page (`/editor/files`). **Show Files** (`Ctrl/Cmd+Shift+E`, registered once by the palette; `app/hooks/use-show-files.ts`) shows the sidebar and focuses its tree on desktop, and opens the Files page on mobile. Both use the `VaultFileTree` tree (selection, keyboard, right-click menus, rename/create in place, Trash with Undo). Both lists offer the same create actions in the same order (`vault-tree/file-create-actions.tsx`): **New File**, **New Folder**, in the Files page's header, the sidebar's Files ⋯ menu, and every folder's and empty-space menu. The Files page's New File / New Folder name the item in place in the selected folder (while a search filters the list, they use the folder picker and name prompt); a note from a template goes in the folder whose menu it came from, else where the template says, and opens in the editor. Neither list has a Refresh button: `useVaultSync` (mounted by `EditorShell`, so on every /editor route) watches the vault folder where the browser can (`FileSystemObserver`, `observeVault`) and rescans after files appear, go away or move, and rescans on focus and on a timer everywhere.
- **Actions**: Create, rename, move, duplicate, and delete files and folders through `useFileSystem`.
- **Tags**: Tags extracted from notes are searchable with the `#` palette prefix.

### Tasks page
The Tasks page (`app/editor/tasks`) is a vault-wide view over the derived task index.
- **Navigation**: Selecting a task (its text, a double-click on the row, or Open Note in its menu) opens its source file and queues the editor to focus its source line. A note indexed without a handle is resolved from the vault by path.
- **Board**: the default view, first in the switcher, lays the same tasks out in a column per status (`[ ]`, `[/]`, `[!]`, `[x]`); dragging a card to another column writes that status back. No new data.
- **Filtering and grouping**: Task text, custom tags, due-date buckets, status/file grouping, and configurable sorting are client-side derived state.
- **Write-back**: Toggling a checkbox patches the original Markdown source line and saves it through the normal file-save path, which refreshes the task index.

### Templates page
The Templates page (`app/editor/templates`, sidebar **Templates**, palette **Open Templates**) is where templates are kept. Templates are used from a note (`/template`, an empty note's buttons, a missing link's picker), never to create or name notes. The app has no daily or periodic sheets of its own.
- **Your templates**: grouped by pack (`groupTemplatePacks`; a pack is a folder in `templates/`, templates in no pack first, under "Not in a pack"), each with **Edit** (opens the template file) and **Delete** (that file to the Trash, with Undo). Each pack has **New** (`createTemplate(pack)`), **Duplicate** and **Delete** (to the Trash, with Undo); the page header has **New template** and **New pack** (`use-template-packs.ts`).
- **Template packs**: the built-in packs (`BUILTIN_PACKS` in `app/utils/templates/template-packs.ts`: Journal, Meetings, Writing, Projects, Engineering) with **Add to vault**, which copies them into `templates/<pack>/` without replacing files that exist (**Add N missing**, **Added**).
- Opened directly (a reload), the page scans the vault once when nothing is indexed.

## Navigation and URLs

Every /editor route shares one frame, `components/EditorShell`: a plain page with the sidebar beside it; (in `layout.tsx`, inside `VaultAccessGate`): the desktop `WorkspaceSidebar` (only the library: the vault switcher, New note, Pinned, Files; the pages, Settings and search are the command palette's, `AppCommands`), the sidebar shortcuts (`Ctrl/Cmd+\`, `Ctrl/Cmd+Alt+S`) and the vault dialogs. Pages render in `components/ShellPage` (a title bar with the `SearchPill`, beside the open sidebar; ← Editor on mobile, which has no sidebar). Searching is always the command palette's (Ctrl/Cmd+K, or the `SearchPill` in the editor's corner and the page title bars). Every place has a URL (`utils/editor-url.ts`), so a refresh or a link lands back on it:

| URL | Shows |
|---|---|
| `/editor?file=notes/plan.md` | The note in front (`hooks/use-active-file-url.ts`: opened, or its tab brought forward, once the vault is readable; then kept in step with the focused tab) |
| `/editor` | The draft |
| `/editor/tasks`, `/editor/templates`, `/editor/trash`, `/editor/files` | Tasks, Templates, Trash (Put Back / Delete, `app/hooks/file-system/trash-ops.ts`), All Files |
| `/editor/tags?tag=release` | Tags: every tag with its count, and the chosen tag's notes (`tags/page.tsx`, inside `<Suspense>`: the chosen tag follows the URL through `useSearchParams`, so a pinned tag clicked in the sidebar rewrites it in place; `editorTagHref` builds the link). The chosen tag's heading (`tags/TagHeading.tsx`) has a **Pin** button on desktop that pins the tag to the sidebar's Pinned section; pinned, it reads **Pinned** and is disabled |
| `/editor/settings?section=editor` | A Settings section (the first one has no parameter) |

Query parameters are rewritten in place (`replaceState`), so switching notes adds no history entries; a note opened from a page goes back to the editor at its URL.

## Editor page hooks (`app/editor/hooks`)

- `use-git-baseline.ts` — `useGitBaseline({ viewRef, vaultHandle, filePath, enabled })`: reads HEAD's text for the open file through `services/git-read-client.ts` and sends it to the Git Changes gutter; re-checks HEAD's stamp on focus, when the page becomes visible and every 5 s while focused, re-reading the blob only when it changed; sets `atom_gitAvailable` (false → the palette command says there's no `.git` at the vault's root); ignores responses for an old path.

The editor route (`page.tsx`) composes these:

| Hook | Purpose |
|------|---------|

## Interactions

1. **Opening a File**: When a user opens a file from the command palette or the file overlay, it calls `openFile` from `useFileSystem`. This reads the file content, sets the document content, and updates the active file handle.
2. **Editing**: As the user types in the editor, the document state is updated in real time.
3. **Saving**: Saving can be manual or automatic. It uses the active file handle to write the current content back to the local disk.
4. **File Synchronization** (`app/hooks/use-file-watcher.ts`): HermesMarkdown picks up external modifications to open files almost immediately in browsers with `FileSystemObserver` (Chromium), and otherwise polls for them (with backoff up to 5 minutes, and immediately when the window regains focus).
    - **Auto-Sync**: If no local changes exist, it automatically reloads the new content from disk.
    - **Conflict Resolution**: If local changes exist and the file was modified externally, a **Conflict Dialog** appears with **Accept Incoming** (reload from disk), **Keep Current** (overwrite on next save), or **Resolve in Merge Editor** (current, incoming and merged result side by side).
5. **Folder Management**: Creating a folder uses `targetDir.getDirectoryHandle(name, { create: true })` and refreshes the directory listing.

## Flow mode (Focus: dim, sentence)

`codemirror/flow-mode.ts` is the two strongest levels of the Focus setting (**Dim other paragraphs** / **Dim other sentences**, Settings → Editor or **Focus: …** in the command palette), read from `atom_focusMode` (`"dim"` → `flowMode("paragraph")`, `"sentence"` → `flowMode("sentence")`) and toggled through a CodeMirror compartment.

`codemirror/git-changes.ts` is the Git Changes gutter (Settings → Editor → View, **Toggle Git Changes**; `atom_showGitChanges`, off by default), in its own compartment. A `StateField` holds HEAD's text (set with the `setGitBaseline` effect, fed by `hooks/use-git-baseline.ts`) and the markers `computeGitMarkers` builds from `Chunk.build` (`@codemirror/merge`): a 3px `--moss` bar per added line, a `--link` bar per changed line, a `--danger` wedge where lines were deleted. Markers map through edits and are recomputed 150 ms after the last one; over 20,000 lines there are none. The gutter sits after the line numbers and fold markers (right of them, next to the text) and takes no width while the baseline is `"off"` (no repository, a binary or huge blob, a read error). The app only reads `.git` (`services/git/`, in the git-read worker), at the vault root of a disk vault.

Typing is never rewritten: Enter is a plain line break (no list or quote continuation, no indent), Backspace deletes one character, a `-` stays a `-`, and a pasted URL or multi-line block lands as it is. Lists and quotes are written by hand, or with Tab / Shift+Tab and the block-type shortcuts.

1. **Paragraph focus**: a view plugin marks the lines of the caret's paragraph (the run of non-blank lines around it) with `cm-flowActive`. While the editor has focus, every other line and block widget fades to 25% opacity. On blur the whole note returns to full strength. At the sentence level, `sentenceRangeAt` finds the caret's sentence inside that paragraph (a `.` `!` `?` or `…` followed by whitespace and a non-lowercase character, a line ending in one, or a line starting a Markdown block) and the rest of the paragraph gets the `cm-flowDim` mark, faded the same way. Marks are re-created spans, so a transition can't run on them: when the caret alone moves to another sentence of the same paragraph, the sentence left gets `cm-flowDimEnter` and the one entered `cm-flowEnter`, one-off 200 ms fade animations (none with reduced motion) that the next update drops. Typing never fades. `atom_toggleSentenceFocus` (Ctrl/Cmd+Alt+F in `use-editor-shortcuts.ts`, **Toggle Sentence Focus** in `SettingsCommands`) switches to `"sentence"` and back to the level before it.
2. **Typewriter scrolling**: a transaction extender adds a centered `scrollIntoView` effect to typing, deletion, undo/redo and keyboard caret movement. Pointer selections and external reloads never scroll. The content gets extra bottom padding so the last line can still reach the center.

Neither part touches the document. The Markdown on disk is unchanged.

## Inline calculator

Math typed on its own line gets a faint `= result` label at the end of the line: `rent = 1200`, `utilities = 180`, then `rent + utilities` shows `= 1380`. Labels are display-only widgets. The plugin never dispatches, so the file, undo history and dirty state are untouched.

- **Files**: `utils/math-eval.ts` (shared safe evaluator: `evaluateMathExpression` with names, `%`, `of` and `1,234` options; `evaluateMath` for `calc(…)=` is unchanged), `utils/note-calc-scan.ts` (line scanner and cache, pure), `codemirror/note-calc.ts` (widget, view plugin and `baseTheme`, registered in `extensions.ts`).
- **Skipped lines**: frontmatter (line 1 `---` to the next `---`), fenced code (backtick or tilde; closed by the same character with at least the opener's length; unterminated fences run to the end), `$$` blocks and single-line `$$ … $$`, blank lines and headings. Skipped lines never get a label or define a variable. An unclosed bare `$$` hides labels for the rest of the note. The scanner can't look ahead, so this differs from `rendered-block.ts`, which doesn't render an unclosed `$$`.
- **Assignment**: `name = expression`, where `name` is one or more words (case-insensitive, `of` reserved). Only a standalone `=` counts, so `==`, `>=`, `<=` and `!=` are never assignments. An invalid right-hand side makes the name undefined from that line on. Reassignment can read the old value (`rent = rent + 100`).
- **Expressions**: `+ - * /`, parentheses, names, `450 + 15%` (relative to the left side), `15% of 200`, and other `%` as a plain fraction. Tabs count as spaces between tokens (`calc(…)=` still accepts spaces only). One leading list marker is stripped. A line that fails to evaluate gets no label.
- **No label** for bare literals (`1200`, `rent = 1200`, `tax = 15%`) or date/phone-like runs (`2026-10-01`, `555-1234`). Results are rounded to 4 decimals with no grouping.
- **AI**: `NOTE_CALC_GUIDE` (`utils/formula-ai-guide.ts`) teaches the chat, Continue writing and new-note generation to write calculator lines instead of computed numbers; `FORMULA_PRESERVATION_RULE` tells every rewrite action to keep them as written. Update the guide when the line rules change.
- **Incremental cache**: `NoteCalcCache` keeps the state after each line (open block, scope as an immutable linked chain). An edit drops entries from its first changed line down. Scanning only goes as far as the last line of `view.visibleRanges`, and labels are built only for visible lines, so variables defined above the viewport still resolve. Each `EditorView` has its own cache.

## Live markers

Performance: CodeMirror draws only the lines in its viewport, and the decorations follow it. `highlight.ts` needs to know what's open above the viewport (a code block or callout changes the lines below), so it saves its reading every 256 lines (`ScanCheckpoint`) and starts from the nearest saved line; an edit drops only the checkpoints below it (`keepCheckpointsBefore`). It decorates only the viewport and stops one line past it. Tag pills, like links, are matched only on the visible lines (plus the frontmatter block). Heading fold chevrons (`codemirror/heading-fold.ts`) are placed from the syntax tree on the visible lines only, and a heading's section end is read only when it's folded. The table grid finds tables incrementally: tables an edit doesn't touch or sit next to move with the text and keep their formula results, and only the edited lines (one either side) are searched again; an edit typing or removing a code fence, `>`, `~` or `<` finds every table again, and one with `#` or a line break re-evaluates every formula (a table's name is its heading). Frontmatter is read from the top only as far as the block goes. `corepack yarn bench` (`codemirror/editor-performance.bench.ts`, not run in CI) times these at 2,000 and 20,000 lines. Links, dates and priorities are matched only on the visible lines (`codemirror/visible-lines.ts`). Frontmatter is found by reading lines from the top (`frontmatterRangeOf` in `codemirror/frontmatter-block.ts`, cached per document) rather than turning the note into a string. The React side skips work when nothing changed: the text the editor just reported isn't diffed again when it comes back as `value`, and the callout chevrons keep the same list across caret moves.

There's one mode: syntax shows where you're writing. Inline marks (emphasis, strikethrough, inline code) show, dimmed, while the caret or selection touches their token (the word or span, edges included); the rest of the line stays rendered. A heading's `#`s and a quote's or callout's `>`s and `[!type]` show on the caret's lines (`codemirror/syntax-reveal.ts`); a heading keeps its size. An editor without focus hides every mark. Heading `#`s and quote `>`s hang in the margin, so those lines don't move; off the caret's lines those margin marks stay in the line, invisible (`cm-marginMarksHidden`), rather than removed, so showing them on a click doesn't re-lay the line and the text doesn't jump (a callout's `[!type]`, inline, is still hidden). List markers, task boxes, code fences, tables and frontmatter keep their own display (`codemirror/live-markers.ts`, a `ViewPlugin` over the visible ranges that reads the Lezer tree, plus the dimming in `highlight.ts`):

- **Inline marks** (`**`, `*`/`_`, `~~`, inline-code backticks) show as typed, dimmed, while the caret or selection touches their token, edges included (`highlight.ts`), hidden elsewhere (`syntax-reveal.ts`).
- **Heading `#`s and quote `>`s** hang in the margin (`cm-marginMarks`, out of the flow), faint, on the caret's lines; a callout's `> [!type]` shows as typed too. Quoted lines get a left border (`cm-liveQuote`). A heading inside a quote or callout hangs its `#`s there too, after the `>`s (`> ## `), so it lines up with the quote's text; one after a quoted list marker keeps them inline. A quoted code block's lines hang their `>`s the same way, and its code is left alone.
- **List markers** (`- `, `1. `, `- [ ] `) stay inline, as typed, muted (`cm-listMarker`), whatever the caret does: a list looks just like its Markdown, so copying it gives what's on screen. Nested items are indented by their own spaces, nothing added or hung; those leading spaces are set in the monospace face (`cm-listIndent`), so each is as wide as a letter and two or four spaces read as a clear step, as in a fixed-width editor. Tab nests an item four spaces in, or at the column the item above's children already use, so a list keeps one indent per level; an item with no item above it at its own level (the first of a list or of a nested level) stays put, since one more level would skip one and read as a code block; numbered items after a moved one renumber straight on (`list-commands.ts`; the palette's Indent/Outdent current item use four spaces too).
- **Tasks** (`- [ ]`, or numbered, `1. [ ]`): the status can be typed in the box (`[/]` in progress, `[!]` on hold, `[-]` cancelled, `[x]` done). The marker carries the status (`cm-listTask`, `data-state`); coloured like the Tasks page's status ring: to do and cancelled faint, in progress `--task-prog`, on hold `--task-hold`, done `--task-done`. Mod-click on the marker moves the task on a status, like Mod-Enter (to do → in progress → done → to do; on hold resumes, cancelled reopens), with its stamps (`cycleTaskBox`); a plain click places the caret.
- **List caret**: the caret goes anywhere on a list item, in front of its `- ` too. Home goes to the start of the item's text (a task's `[`), and again to the start of the line (`list-commands.ts`).
- **Callouts** are one tinted card (`cm-callout`, `highlight.ts`). The text after a body line's own `>`s is styled like any other line (`codemirror/highlight-blocks.ts`, shared with the top level): headings take their size and start at the card's text edge like the body (insets are in body-text units; their `#`s hang in the margin with the `>`s), lists and tasks their markers and states (nested items indented after the `> `), tables are the same editable grid as anywhere else (below), fenced code is a code block of its own inside the card (`cm-callout-codeblock`, `-start`/`-end` on the fences: a faint rounded panel from the card's text edge, the code monospaced and inset in it), and a quote inside stays a muted quote, though a heading or list item in it (`> > ## Title`) is styled as one. Export and print already render a callout's body as Markdown of its own (`utils/print/note-html.ts`).
- **Heading sections** fold (`codemirror/heading-fold.ts`, CodeMirror's own folds): a top-level `#`–`######` heading (not in a quote, callout, list, code or the frontmatter) hides everything up to the next heading of the same or a higher level, keeping the blank lines before it. The frontmatter folds the same way, as a section of its own: the whole block, opening `---` included, becomes one line on its panel, "Frontmatter · title · #tags" (`frontmatterSummary` in `codemirror/frontmatter-block.ts`; up to three tags, then +N), which unfolds it on click; its chevron sits just outside the panel and isn't hidden on the caret's lines. A chevron hangs in the leading margin where the `#`s do: shown on hover (faintly always on touch screens) and while folded, hidden on the caret's lines where the `#`s show. A folded heading ends in a `…` that unfolds it. Ctrl/Cmd+Shift+. folds or unfolds the caret's section, Ctrl/Cmd+Shift+, unfolds every heading (callouts and `<details>` keep their written state); both are in the palette. Folds aren't written into the note: `useCodeMirrorHeadingFold` keeps them for the visit in `atom_headingFolds`, by path and heading line.
- **`<details>` sections** (raw HTML `<details><summary>Title</summary> … </details>`, found by the line scanner `app/utils/details-blocks.ts`; not inside fences, frontmatter or quotes; an unclosed one is plain text) fold like callouts (`codemirror/details-fold.ts`, chevrons from `use-codemirror-callout-fold.ts`): the summary's line stays, the rest through `</details>` folds. Without an `open` attribute a section starts collapsed; the chevron adds or removes `open` in the note (one undo step). The summary is bold; its `<summary>` tags (and an inline `<details>` tag) are hidden off the caret's lines and dimmed on them; a `<details>` or `</details>` on a line of its own is always shown, dimmed. Exports render each as a native `<details><summary>`: Export as PDF and embeds open, Export as HTML as the note has it.
- **Left alone**: fenced code shows its fences as typed, and tables, setext headings and frontmatter keep their own display.

## Rendered blocks (Mermaid and math)

`codemirror/rendered-block.ts` works like the table grid. A `StateField` finds closed top-level ```` ```mermaid ```` fences, ```` ```math ```` / `latex` / `tex` fences, and `$$` blocks outside code (either `$$` on its own lines or `$$ … $$` on one line). It replaces each one with a block widget showing the rendered diagram or formula. The ranges are atomic, so the caret moves past a preview in one step.

`codemirror/markdown-problems.ts` checks the note `PROBLEM_CHECK_DELAY_MS` (1.2s) after typing stops, never per keystroke: frontmatter is parsed with `js-yaml` (loaded on first use; `{{field}}` template fields are swapped for a placeholder first), and the syntax tree gives fences with no closing mark, plus `$$` lines outside code with no partner. Each problem is a block widget just above its block (above line 1 for frontmatter), such as "Frontmatter isn't valid YAML on line 4: bad indentation…", with a **Go to line N** button that puts the caret there. An edit clears the notices until the next check. Fences aren't checked until the whole note is parsed.

1. **Rendering**: `utils/rendered-block-cache.ts` loads `mermaid` (`utils/render-mermaid.ts`, `securityLevel: "strict"`) or KaTeX (`utils/render-math.ts`) on first use and caches results and measured heights by kind + theme + source. Widgets only re-render when their source or the app theme changes, so edits elsewhere in the note leave them alone. Invalid source shows the error and the raw source instead.
2. **Editing**: double-clicking a preview, its **Edit** button (always visible on touch screens), or Ctrl/Cmd+Shift+Enter with the caret beside it opens `RenderedBlockSourceDialog`. The dialog has a live preview. **Save** (or Ctrl/Cmd+Enter) writes the new body with `applyRenderedBlockEdit` as a single undoable change. Inserting an empty block from the slash menu opens the dialog straight away, since the caret would otherwise land inside a hidden range.
3. **Viewer**: for Mermaid, **Open viewer** in the dialog opens `MermaidDialog` (zoom, pan, SVG download).

## Note embeds

`codemirror/note-embeds.ts` shows the file named on a line holding only `![[Name]]` (or `![[Note#Heading]]`, alias allowed) or `/path.ext` as a read-only block widget after that line; the line itself stays as typed and editable. A note shows its text (or one heading's section), a `.csv` a table, an image (`png`, `jpg`, `gif`, `webp`, `svg`, `avif`, `bmp`) the picture, and a code file (`ts`, `py`, `json`, `sql`, … `txt`, `log`) a code block coloured with the editor's highlight style (`utils/highlight-code.ts`, the language picked from the file name and loaded on first use; at most `MAX_CODE_LINES` lines). Other extensions aren't embeds. `utils/note-embeds.ts` holds the pure parts: `parseEmbedLine` / `findEmbeds` (embed lines outside fenced code, with their kind), `embedSection` (frontmatter and board scene removed, or just one heading's section), `fileCandidatePaths` (a non-note file next to the note, then from the vault root), and `expandEmbeds` (the compiler below).

1. **Loading**: `hooks/use-note-embeds.ts` (in `MarkdownEditor`) resolves each note with `resolveFileMetaByName` and takes an open tab's text from `atom_openFiles` (through a narrowed atom, so typing elsewhere doesn't re-render); everything else goes through `utils/embed-files.ts`, which re-reads a file (or makes a new image object URL, revoking the old one) only when its modified time changed. It pushes `{ contents, open }` into the editor with the `setNoteEmbeds` effect. Files are checked again on each vault scan and whenever the window comes back into view (`focus` / `visibilitychange`), so a CSV edited in a spreadsheet app updates as soon as you switch back. A missing file, the note itself and a veiled private note get a message instead.
2. **Cost while typing**: an edit only rescans the note when it touches a line starting with `![[`, `/` or a code fence, before or after the change (`touchesEmbedLines`); other edits just map the widgets. The hook gates its scan with one regex test, and reloads embeds 200 ms after the last change, so typing in an embedded note's own tab doesn't redraw the embed on every key.
3. **Rendering**: an embedded note's section goes through `noteToHtml` (everything escaped), its Mermaid and math through `rendered-block-cache`. Embeds inside an embedded note show as names in the editor. The title button opens a note like its wikilink; other files' titles are plain text.
4. **Compiling**: Export as PDF and **Export as Compiled Markdown** (`hooks/use-download-compiled.ts`) run `expandEmbeds` through `hooks/use-embed-reader.ts`: every embed line becomes what it embeds, nested notes included up to `MAX_EMBED_DEPTH`; a note already being filled in higher up keeps its line, so loops stop. Code files become fences (`codeToFence`), images image links from the vault root, and relative images inside an embedded note are rewritten from the vault root (`rootImageLinks`).
5. **Autocomplete**: `/` at the start of a line also lists vault notes matching what follows (`matchEmbedFiles` in `codemirror/slash-menu.ts`, fed by `SlashMenuCallbacks.embedFiles`); picking one writes `/<path>.md`. `codemirror/embed-ghost.ts` adds the inline version: with the caret at the end of a line holding only `/` and the start of a note's path or name, the rest of the best match (`bestEmbedCompletion`: a path prefix, else a name prefix, shortest path first) is a faded widget after the caret, and Tab or → (at `Prec.highest`, ahead of list indenting and the popup) replaces the line with `/<path>.md`. Only notes are in the vault index, so neither offers other files.
6. **`/board`**: the slash entry (`BOARD_LINK_SENTINEL`, shown with `onInsertBoard`) runs `hooks/use-insert-board-link.ts`: it asks the name, creates the board with `createLinkedBoard` (from `use-template-create.ts`, without opening it; an existing board of that name is linked as it is) and inserts `[[<path>]]` where the caret was.

## Table Flow

Tables never show their pipe syntax. Every valid GFM table renders as an
inline, spreadsheet-style grid whose cells are edited in place, while the
Markdown source stays the single source of truth.

### Inline grid (`codemirror/table-display.tsx`)

1. **Detection**: a `StateField` walks the Lezer syntax tree for `Table` nodes (so pipes in code blocks are never tables) and replaces each with a block widget. After the first pass it updates incrementally (`updateTables`, see Performance above). Tables are atomic ranges; when the editor caret arrives at one (arrow keys, undo), focus hands off to the nearest cell (first cell from above, last from below).
2. **Editing**: each cell is its own `contenteditable`. Unfocused cells show rendered inline Markdown (`utils/inline-markdown.ts`); the focused cell shows its raw text (`**bold**`, links…). Every keystroke is written back as a minimal change to that cell's source range. Undo/redo, autosave and merges always see the table as displayed. Typed pipes are stored escaped (`\|`).
3. **Keyboard**: Tab / Shift+Tab move between cells, and Tab in the last cell adds a row. Enter moves down, adding a row at the bottom. The arrow keys cross cell edges and leave the table at its borders. Escape leaves the table. Alt+↑/↓ move the row, Ctrl/Cmd+Alt+Shift+←/→ move the column, Ctrl/Cmd+Alt+↑/↓ (or `[` / `]`) insert a row above / below, Ctrl/Cmd+Alt+←/→ (or `-` / `=`) insert a column before / after (`TABLE_INSERT_KEYS`), Ctrl/Cmd+Enter inserts a row below, Ctrl/Cmd+Shift+Enter shows the table's pipe source, Ctrl/Cmd+Shift+Backspace deletes the row, and Ctrl/Cmd+B / I / E wrap the selection in bold / italic / code.
4. **Paste**: plain text pastes into the cell. TSV (from a spreadsheet) or multi-line CSV fills cells starting at the focused cell, growing the table as needed.
5. **Edit as Markdown** (`codemirror/table-source.ts`): the menu item (or Ctrl/Cmd+Shift+Enter) swaps the grid for its pipe source as plain text, so a table that parsed wrong (a line typed under it without a blank line becomes a row, a missing pipe) can be fixed by hand. It stays text while the caret is in that block of non-blank lines, even when an edit briefly stops it parsing as a table, and renders as a grid again once the caret leaves.
6. **In a quote or callout** (`> | a | b |`): the grid takes the rows' whole lines, `>`s included, and wears the block's frame (`table-quote-frame.ts`: the callout's tint, rounded at the bottom when the table ends it, or a quote's bar). The table code reads such a table through a mask (`utils/quoted-table.ts`): each row's `>` prefix becomes spaces of the same length, so every offset is still the document's, and `findTableInState` puts the prefix on `TableInfo.quotePrefix`. Rewrites keep the indent (`indentRows`) and `applyTableChangeFor` puts the prefix back (`restoreQuotePrefix`), so added rows and columns stay in the callout. In a callout a bare `>` line counts as blank for Edit as Markdown.
7. **Source hygiene**: when the caret leaves a table, its column padding is realigned (`hooks/use-codemirror-table.ts`). Tables written without outer pipes get them on first edit. Both are kept out of undo history because nothing visible changes. They're applied as minimal padding-only changes (`paddingChanges`), never as one whole-table replacement: earlier undo events are mapped through such changes, and a whole-table rewrite would silently invalidate every earlier cell edit.

### Table menu (`codemirror/table-handles.ts`)

Nothing is drawn on top of the cells. Table actions live in one menu with **Row** (insert above/below, move, delete), **Column** (insert left/right, move, sort, align, delete) and **Table** (edit as Markdown, copy as CSV / JSON, delete with a confirming second click) sections. Open it either way:

- **Right-click / long-press** a cell. The menu opens at the pointer.
- **Row numbers and column letters**: while a table is being edited, spreadsheet-style rulers appear in gutters reserved above and left of it (A, B, C… / 1, 2, 3…, matching formula addressing). The row-number gutter hangs in the page margin like a heading's `#`s, so the table lines up with the text. Clicking one opens the menu for that column or row.

All structural edits go through `codemirror/table-commands.ts` as one isolated undo step each. That module holds the keyboard commands (bound in `table-keymap.ts`, `tableKeyBindings`, shared with the table generator tool in `app/tools/table/`) and re-exports the shared primitives in `table-edit.ts` and the menu actions in `table-menu-actions.ts`. The widget itself is split into `table-display.tsx` (state field, widget, caret entry), `table-source.ts` (the Edit as Markdown state), `table-cell-dom.ts` (rendering, caret offsets, `calc(…)=` typed in a cell, `openCellLink` for a Ctrl/Cmd+clicked cell link: a web link opens in a new tab, a vault path is sent up as `FILE_LINK_EVENT`, `utils/open-link.ts`, which `useCodeMirrorFeatures` opens) and `table-cell-handlers.ts` (cell events, menus, rulers).

### Formulas (`utils/formula-engine.ts`, `codemirror/table-formulas.ts`)

A cell starting with `=` is a formula (`=SUM(B2:B5)`, `=AVERAGE(B2:D2)`, `=IF(...)`, …; A1 refs with the header as row 1). While the table display field builds the grid, it evaluates every table in one pass. Tables are named by the heading above them, so cross-table refs (`=SUM(Income!B)`) resolve. Unfocused formula cells show the computed value (raw formula as tooltip); the focused cell shows the formula. Cross-note refs (`=[[Budget]]!B5`) come from `hooks/use-cross-file-tables.ts`, which reads the referenced notes asynchronously and pushes a snapshot into the editor via the `setFormulaFileTables` effect. **Sum column** in the table menu writes `=SUM(...)` into a totals row: the last row, if it holds an aggregate (SUM/AVERAGE/COUNT/MIN/MAX), else a new one. Rows added at the end go above the totals row and extend its ranges. A range that covers the formula's own cell skips that cell rather than reporting `#CIRCULAR!`.
