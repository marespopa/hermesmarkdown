# companion

The AI companion: one AI in the app. A panel docked on the window's trailing edge, hidden until opened (Ask AI, Ctrl/Cmd+J, the slash menu, the selection toolbar's Ask AI, the mobile file bar). Open, it takes room and the page moves over (`--content-right`, `EditorShell`). It streams its replies, reads the vault, edits and rewrites notes and code files, searches inside them, keeps a checklist for multi-step plans (`update_plan`), creates files and folders, renames and moves items, moves them to the Trash after asking, and saves templates. Every change saves at once, and a turn's changes are one group on the app's file-undo stack, so they undo together (Undo turn, ⌘Z in Files, a toast's Undo).

| `companion-commands.ts` | The companion's own commands, ahead of skills: `/new` / `/clear` (new chat) and `/compact` / `/summarize` / `/summarise` (words after it say what to keep); the summary's prompt (`transcriptText`: typed text, replies, one line per tool call, never context or results) and `summaryMessage`, the user turn (`metadata.summary`) a compacted thread starts with. | `companion-messages.ts` | A user turn's parts (typed text, then a `--- CONTEXT ---` part with a `/command`'s `--- SKILL ---` block first, then images), `forModel` (the last `FULL_TURNS` (6) turns sent whole; older turns' long tool results and context parts become `LEFT_OUT`, their images dropped; the saved thread is untouched), `MAX_TOOL_ROUNDS` (60) and `shouldContinue` (resend once the last step's browser-run calls all have results; provider-run ones, `WEB_TOOL_NAMES`, never call for a round), tool part views. |
| `reply-html.ts` | A reply's Markdown as safe HTML (`noteToHtml`; no images, diagram and math sources as code). |
| `companion-prompt.ts` | `COMPANION_PROMPT` and `buildCompanionSystemPrompt` (adds the skill list, `skillListBlock`: each skill's command and description, never its text, so the prompt stays cacheable). |
| `use-companion-tools.ts` | Runs each tool call in the browser: note tools (`ai-chat/use-note-tools.ts`), `list_folder`, `read_file` (a line range; a long file ends with the `startLine` to ask for next), `search_files` (reads each file on the main thread, so the palette's search worker is left alone), `update_plan`, `get_active_note`, `load_skill` (`ai-chat/use-chat-skills.ts`), the writes and the organising tools. Also used by `hooks/use-webmcp-tools.ts` for browser agents' writes. |
| `use-companion-writes.ts` | `edit_file`, `write_file` (replaces a file's whole text, or creates it), `edit_code_block`, `create_file` (a new note gets `title` and `created` frontmatter, `withNewNoteFrontmatter`; a new note's frontmatter, or one an edit changed, is kept valid YAML, `repairFrontmatter`), `create_folder` and `create_template` (`lintTemplate` first; problems go back to the model, nothing is written; never replaces a template) through `useNoteBuffer().writeThrough` (disk wins over tab text), each a step of the turn's undo group (`recordSteps`, `turnUndoGroup`); `undoTurn` through the app's `undoFileOperation`. | `use-companion-organise.ts` | `rename` (`renameFile`; links follow; a file keeps its extension), `move` (`moveItems`, into an existing folder) and `trash` (`trashItems`, after the card), in the turn's undo group; private notes and folders holding one are never touched. |
| `trash-confirm.ts` | A waiting trash call's paths (`atom_trashRequests`, by toolCallId) and its answer; Stop and New chat keep the files. |
| `turn-journal.ts` | Pure helpers over a turn's undo steps: `recordContent` (keeps the first text from before, unless something moved there since), `recordCreate`, `changedPaths`, `trashedCount`. |
| `use-open-companion.ts` | Opens the panel with the note in front and its selection; never for a private note. |
| `tools/path-guard.ts` | Paths normalised, kept in the vault, never in `.hermesmarkdown/` (Trash); `guardItemPath` (any file or folder) and `guardNewName` for rename. |
| `tools/read-tools.ts` | The read tools' answers (private notes listed as "private (hidden)", 40 KB per file, 100 entries per page), code blocks, chip labels. |
| `tools/search-tools.ts` | `search_files`' pure half (matcher, files to search, matching lines, answer; private notes never searched) and `update_plan`'s answer. |
| `tools/edit-tools.ts` | `applyEdits` (each `find` must match once, else the count goes back to the model) `replaceCodeBlock` `withNewNoteFrontmatter` (adds a missing `title` and `created` to a new note) and `repairFrontmatter` (frontmatter that isn't valid YAML gets quotes around each top-level value YAML can't read alone, such as a title with a second `: `; left alone when that doesn't fix it). js-yaml loads on first use (`utils/load-yaml.ts`). |

Server side: `app/api/ai/companion/route.ts` (streams; tools without `execute`, plus Claude's own `web_search` when the user turned it on, and its sources; `keep-alive.ts` sends an SSE comment at once and every 5 s so a host's proxy doesn't end a long think as an Inactivity Timeout), `companion-tools.ts` (`COMPANION_TOOLS`, `webSearchTool` by model, `foldSystem` for Gemini, `withPromptCache` for Claude: the system prompt, and with it the tools, plus the thread's last message marked `cacheControl: ephemeral`, so each tool round and the next turn read the prefix from Anthropic's prompt cache), shared `app/api/ai/providers.ts` and `errors.ts`. Tool schemas: `app/services/companion-tool-defs.ts`. State: `app/atoms/companion-atoms.ts`.
