# MarkdownEditor

Description: CodeMirror 6 Markdown editor for one pane. It adds inline pills and callouts (links, dates, tags), an inline editable table grid with spreadsheet formulas (including cross-note references), slash templates, inline-rendered Mermaid diagrams and display math (double-click to edit the source), a code-language picker, image paste, CSV-paste-to-table conversion, callout folding, collapsible frontmatter (collapsed, it is one quiet summary row — "▸ Properties · draft #work #ideas +1 · title, created, +2": `status` and up to three `tags` as tag-pill chips coloured like the same inline tag, then the first three other top-level keys by name (`frontmatterRowSummary`) — that expands the block on click or when the caret moves in; expanded, the same row ("▾ Properties") is the top row of the YAML's tinted panel and collapses it again, so the toggle never moves; that note only — every split pane showing the same note follows (`atom_frontmatterCollapsedByFile`, in memory, dropped when the note's last editor closes); the block that appears fades in briefly (not on file open, not with reduced motion); a click on the row — not the caret moving in — is remembered in `atom_frontmatterCollapsedByDefault` (no setting or command of its own), and notes opened later start that way while open ones keep their state), no tint on the caret's line, optional line numbers aligned with their text (`codemirror/line-numbers.ts`: gutter cells beside headings and fenced code take the line's padding and line height, mirrored in `editor-typography.scss`), optional invisibles (`codemirror/invisibles.ts`, `atom_showInvisibles`: ¶ on empty lines, dots for spaces, arrows for tabs), an optional flow mode (`codemirror/flow-mode.ts`: dims all but the caret's paragraph and keeps the caret line centered), and live markers (`codemirror/live-markers.ts`: `**`, `_`, `~~` and inline-code backticks show only while the caret touches their span; a heading's `#`s and a quote's or callout's `>` always sit in the margin, out of the text flow, and show faintly only while the caret is on their line (elsewhere they're transparent, so both states lay out the same and the text never moves; a row holding only its marks, like `## ` before the first letter, keeps its height); list markers never change with the caret — • / ◦ bullets, clickable task checkboxes, muted fixed-width numbers — and wrapped items hang at their text; callouts show their type as a label, fenced code fades its fences away from the caret and shows the language; an unfocused editor shows no marks). The editor is a paper panel: a rounded `--surface` card with a hairline border and soft shadow, inset on the chrome canvas (`editor.scss`), on desktop and mobile alike; its side edges line up with the first tab (1rem, 1.25rem from 640px, single pane or split). The panel carries a fine paper grain (`--paper-grain`, a tiled SVG noise defined per theme in `globals.scss`) that moves with its element (not fixed to the viewport, which shimmered and repainted every frame while the sidebar slid). The text is set as a reading page (`editor-typography.scss`): wide page margins that grow with the pane (20px on phones up to 56px on wide panes, `useEditorAppearance`), a centered column that grows with the sheet up to a fixed width that the text size doesn't change (`--editor-measure: clamp(36rem, 85%, 44rem)`, at most 704px; with Full Width on (`atom_fullWidth`, Settings → Editor) the sheet gets `data-full-width` and the column fills it, inside the page margins, the `.editor-measure` wrapper), slightly softened body text, plain greedy wrapping (no `text-wrap: pretty` or `balance`, which re-break earlier lines as you type and make words hop under the caret), and a heading scale (2em / 1.5em / 1.25em / 1.125em / 1em / 0.875em, from the `cm-heading-N` line classes in `codemirror/highlight.ts`) with tighter tracking and no padding above or below, so only real blank lines space a heading from its neighbours. The exception is H1, which keeps 0.9em above it to set the title apart from the Properties block; a heading on a note's first line has none.

## Local State & Storage
- State: `atom_activeEditorView`, `atom_isEditorFocused`, `atom_fileMetadata` (to resolve cross-note formula refs), `atom_wordWrap`, `atom_lineNumbers`, `atom_vimMode`, `atom_flowMode`, `atom_frontmatterCollapsedByDefault`, `atom_frontmatterCollapsedByFile`, `atom_vaultHandle`, `atom_currentDirectoryHandle`, `atom_pendingScrollTarget`, `atom_isAiConfigured`, `atom_aiBuilderRequest`. Pill and dialog state is local useState.
- Persistence: Editor preferences live in `localStorage` (`wordWrap`, `lineNumbers`, `vimMode`, `flowMode`, `frontmatterCollapsedByDefault`). Pasted images are written into the local vault through the File System Access API (`savePastedImage`).
- An empty note (not a template) shows [EmptyNoteTemplates](EmptyNoteTemplates.md): template pills that fill the note in one click, gone as soon as there is text. Every template insert (pills, `/template`) plays a short slide-in on the text (`insertExpandedTemplate` adds `cm-template-in` to the content for 260ms).
- Any other note can be saved as a template (`/save-template` slash entry, `onSaveAsTemplate`, and the palette's **Save as template…** through `hermes:save-as-template`; `useFileSystem().saveAsTemplate`, `use-template-save.ts`), named after its first heading. The palette's **Insert template…** (`hermes:insert-vault-template`) opens the template picker for the active pane; selected text fills `{{selection}}` and is replaced. Blanks a template leaves (`{{task_1}}`) show as grey pills in every note (not in code) and Tab / Shift+Tab select them (`codemirror/template-blanks.ts`; Esc turns that off for the note; "Template ready ✦" once none are left; a click on a blank pill selects it).
- A note in the templates folder is a template note (`use-template-note.ts`, which also owns save-as-template and the palette events: `isTemplatePath` with `atom_templatesFolder`). It shows [TemplateStrip](TemplateStrip.md) above the text; its fields render as plain-language pills ("Today's date", "Ask: Owner"; `codemirror/template-field-pills.ts`, switched on with the `setTemplateNote` effect; the source shows while the caret touches a field; unknown tokens stay as typed); and `onInsertTemplateField` / `onAskTemplateQuestion` go to the slash callbacks, which turns on the **Template field** slash entry (`/field`) and the `{{` field menu (`codemirror/template-field-completion.ts`, plain names from `app/utils/templates/template-fields.ts`, matched by token name or a word of the name). Picking a field inserts the whole token, replacing a `}}` already after the caret; **Ask a question…** / **Blank to fill in…** ask for the name in a dialog and insert `{{prompt:Question}}` / `{{Name}}`. `{{date}}` / `{{time}}` typed by hand are not taken for the `{date}` / `{time}` shortcodes in any note.
- Features come from composable hooks in `../hooks`: `use-editor-appearance`, `use-codemirror-{editor,features,templates,table,image,code-language-picker,callout-fold,frontmatter-fold}`, `use-vault-template-insert` (the slash menu's **Template** entry, `/template` or `/tpl`, offered while a vault is open: pick a vault template, answer its prompts, then insert it at the caret as one undo step with the caret at `{{cursor}}`; an empty note gets the whole template including non-routing frontmatter, otherwise only the body; nothing is inserted if the editor went away meanwhile), and `use-cross-file-tables` (reads notes referenced by `=[[Note]]!B5` formulas and pushes them into the editor via `setFormulaFileTables` from `codemirror/table-formulas.ts`).

## Dependencies
- Core: `@codemirror/view`, `DatePickerCallout`, `WikiLinkDialog`, `TaskDialog`, the render pieces in [`markdown-editor/`](markdown-editor/README.md) (`EditorPills`, `LinkInsertDialog`, `FoldChevrons`, `VimStatusPill` with `useVimStatus`), `useEditorPasteHandlers` ("Convert to table?" confirm on CSV paste, image saving), `useScrollToPendingTarget`, `useFileSystem`, `useKeyboardInset`.
- Zero-Cloud: No network or telemetry side effects. Opening a link pill calls `window.open` after a user click. AI actions only set `atom_aiBuilderRequest`; the request itself is made by the AI dialogs.

## Quick Usage
```tsx
import MarkdownEditor from "./MarkdownEditor";

<MarkdownEditor value={content} onChange={setContent} filePath={path} isActivePane />
```

## Props Overview
| Prop | Type | Default | Description |
|---|---|---|---|
| value | `string` |  | Document text |
| onChange | `(value: string) => void` |  | Change handler |
| filePath? | `string` | `"draft"` | Vault path (for image paste, scroll targets and formula refs) |
| placeholder? | `string` | `"Type / for templates"` | Empty-state text |
| onWikiLinkClick? | `(name: string) => void` |  | `[[link]]` navigation (`PaneLeaf` passes `openOrCreateLink`, which also creates missing notes) |
| isActivePane? / isSplit? | `boolean` |  | Pane context |
