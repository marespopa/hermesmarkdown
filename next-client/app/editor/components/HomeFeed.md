# HomeFeed

Description: The vault's home screen — recent notes, newest first, in the editor's column width. A greeting for the time of day ("Good morning" from 5:00, "Good afternoon" from 12:00, "Good evening" from 17:00, "Up late" from 22:00), with `atom_userName` when one is set (from the welcome wizard's first step) ("Good morning, Ada!"; "Good morning!" without one) sits above a large weekday header with an accent dot (month and day on the right). Under it, a week strip shows the seven days ending today, with a dot on each day that has notes; clicking a day selects its first (newest) note and scrolls it to the top (`scrollToIndex(…, { align: "start" })` when virtualized), and the selected row's day is highlighted in the strip. Days without notes are dimmed and inert, and the strip is hidden while the feed is empty. Then the notes: the first note of each day carries a day label in the left gutter ("Today", "Yesterday", the full weekday for the rest of the past week, a short date after that), and each note shows its title, up to three lines of plain-text preview, and the file name with its extension in small, faint type (not for sensitive notes). The selected or hovered row is a rounded fill.

Pinned notes (`atom_homePinnedPaths`, kept per vault, newest pin first) sit above the days under one "Pinned" gutter label and leave their day's group. Each row has a pin button at its top right, shown on hover, keyboard focus or selection ("Pin to Home" / "Unpin from Home"), and hidden on touch screens (`hover: none`). There, a long press on a row (`useLongPress`, 500 ms, cancelled by lifting or moving the finger) opens the row's menu: **Open** and **Pin to Home** / **Unpin from Home**; a right-click or the context-menu key opens the same menu anywhere. The "Pin to Home" / "Unpin from Home" palette command does the same for the open note. Pins follow a renamed or moved note (`atom_remapVaultPaths`), and deleting a note or its folder unpins it (`atom_forgetHomePins`); a pin whose note is missing or hidden by Privacy Mode is skipped. The week strip still counts pinned notes on their day, but jumps to the day's first unpinned note when it has one. A floating bar at the bottom holds the search pill and a `+` new-note button. The pill is the command palette's search field at rest. It shares a view-transition name with that field, so clicking it (or typing on the feed, or pressing ⌘K) morphs the pill into the palette, and closing morphs it back. Both use the same icon, type size and "Search or create a note…" wording, and the palette's "Create '…'" row makes new notes. An empty vault shows the header and a quiet "Start writing" button. Large vaults: indexing dates every note first (a stat pass), so the feed is in the right order almost at once. Notes then show their day label with a placeholder preview until parsed. Parsing runs newest first, so the rows at the top fill in first, and unchanged notes come straight from the IndexedDB cache. Notes that can't be dated sort last, with no label. While the indexer runs, a status line cycles through verbs ("Indexing notes…", "Gathering notes…", "Reading notes…", … every 0.9 s, each indexing run picking up at the next verb; screen readers hear a steady "Indexing notes"), and until the first notes are listed the feed shows three pulsing skeleton rows in place of the "Start writing" button.

Sensitive notes (frontmatter `sensitive: true`, `private: true`, or a `sensitive` / `private` tag) follow Privacy Mode (`atom_privacyLevel`, Settings → Privacy): **Show titles** (default) shows the title with a lock and replaces the preview with fixed bullets, so the real text never reaches the page; **Blur previews** shows the real preview blurred until the row is hovered or keyboard-focused; **Hide notes** leaves them out, with day labels recomputed. Rows come from `atom_noteDisplayItems` (the display factory in `app/utils/note-display.ts`), never from the raw preview. A sensitive row's accessible name is "<title> (sensitive)", since the row label overrides the lock badge.

Keyboard: `j`/`k` or arrows move, Enter opens, Escape returns to the workspace, and any other printable key opens the palette with that key typed. Keys with Ctrl/Cmd/Alt, keys typed in inputs or dialogs, and keys while a menu is open (the vault menu or a row's; Escape then closes only the menu) are ignored.

With no vault open (`hasVault` false) the feed still shows, with the same header but no week strip or note list. In their place, `FeedStart` lists recently opened vaults (`RecentVaultList`: one click reopens one, × drops it from the list), then offers the vault actions ("Open a vault to see your notes here.", via `VaultActionButtons`) and "Or just write": **New Note** (blank draft) and **Open File…** (`onOpenFile`, a file from the device into the draft). The search pill reads "Search commands…" and opens the palette in command mode.

With a vault open, a bar at the very top of the column (`FeedVault`, above the greeting with the header's padding between them) names the vault — the display name of a browser or GitHub vault, else the folder name — and where it lives ("Folder on this device", "Stored in this browser", "GitHub"), The name is the one vault menu ("<name>, vault menu"): the 5 newest recently opened vaults (the open one left out; see `useRecentVaults`), then **Open vault…** and **Create vault…** where disk folders are supported and **Browser vaults…** where browser storage is, then **Refresh vault** and **Close vault**. A folder on disk may ask for access again when reopened; a browser vault that no longer exists is dropped from the list instead of being recreated empty; a GitHub vault reopens from its local copy, as on startup. Below the `sm` breakpoint the bar shows only the name (where the vault lives gives way), and the name is at least 40px tall. Closing asks first (the same confirm as the "Close vault" command) and leaves the feed open as the no-vault start.

Shown by the editor page in place of the workspace while `atom_homeFeedOpen` is true: with no vault, once per tab after the saved vault has had its chance to restore (`useVaultOpenBehavior`, keyed `no-vault`); whenever a vault opens (there is no setting to skip it; once per vault per tab — `useVaultOpenBehavior` records it in sessionStorage, so refreshing a tab that was on a note stays on the note), from the Home button in the pane header / mobile header, or the "Home feed" command. Those go through `atom_goHome`: when the feed is already open it bumps `atom_homeFeedTopRequest` instead, and the feed scrolls back to the top (smoothly, unless reduced motion is on) and selects the newest note. Opening any file closes it (`useOpenFile`). The open state is mirrored in the URL as `/editor?view=home` (`useHomeFeedUrlSync`, rewritten in place with `history.replaceState`, so no remount and no history entries): a link or refresh with that param opens the feed once the vault is restored.

## Local State & Storage
- State: `atom_fileMetadata`, `atom_noteDisplayItems` (privacy view of each note), `atom_indexerState`, `atom_userName`, `atom_homeFeedTopRequest` and `atom_homePinnedPaths` (read); `atom_toggleHomePin` (write); selection is local. Above 100 notes the list is virtualized (`@tanstack/react-virtual`, rows measured, header as scroll margin), so only the rows in view plus overscan are in the page, however far you scroll. Keyboard selection scrolls with `scrollToIndex`.
- Persistence: Pins only, in `localStorage` (`hermes_home_pins`, keyed by `atom_vaultKey`; see `app/atoms/home-pin-atoms.ts`). Titles, dates and previews come from the metadata index (`preview` is computed by the metadata worker).

## Dependencies
- Core: [`home-feed/`](home-feed/README.md) (`FeedVault`, `FeedHeader`, `WeekStrip`, `FeedRow`, `FeedStart`, `FeedBar`, `feed-model`), `Button`.
- Zero-Cloud: No network or telemetry side effects.

## Quick Usage
```tsx
<HomeFeed onOpenNote={open} onNewNote={newNote} onSearch={openPalette} onClose={closeFeed} />
```

## Props Overview
| Prop | Type | Default | Description |
|---|---|---|---|
| onOpenNote | `(path: string) => void` |  | Opens a note by vault path |
| onNewNote | `() => void` |  | Starts a blank draft |
| onSearch | `(initialQuery?: string) => void` |  | Opens the command palette, optionally prefilled |
| onClose | `() => void` |  | Leaves the feed |
| isSearchOpen? | `boolean` | `false` | Palette open: the pill hides and hands its transition name to the palette field |
| hasVault? | `boolean` | `true` | False with no vault: vault actions and ways to start writing replace the notes |
| onOpenFile? | `() => void` |  | The no-vault "Open File…": a file from the device into the draft |
