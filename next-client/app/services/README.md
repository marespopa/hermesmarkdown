# Services

Non-React modules: IndexedDB persistence, browser storage, file writing, vault archives, and AI. Client services run in the browser.

## Storage

Atom persistence uses Jotai `atomWithStorage` (`localStorage`) directly in `app/atoms/*`.

- `metadata-cache.ts` — IndexedDB cache of each vault's parsed metadata (tags, links, frontmatter, tasks, word count, preview), keyed by `atom_vaultKey`. On reopen, notes whose modified time matches are reused instead of re-read. It's a separate database from `idb.ts` and is versioned (`METADATA_CACHE_VERSION`), so parser changes invalidate it. It stays on the device and falls back to "nothing cached" when IndexedDB is missing or fails.
- `idb.ts` — IndexedDB wrapper for the vault `FileSystemDirectoryHandle` (save / load / clear, `verifyPermission`, `queryPermission`), the browser vault descriptor and registry (`renameBrowserVaultDescriptor` updates both, by id), `registerBrowserVault` (adds to the registry without making it the last vault), and `listKeys` / `deleteKeys`. Saving one vault kind clears the other. Permission helpers treat handles without a permission API (Safari, Firefox, browser storage) as granted. Separate from atom persistence. `readKey` / `writeKey` read and write one key of its store. No-op if IndexedDB is missing.
- `recent-vaults.ts` — Vaults opened on this device, newest first, at most `MAX_RECENT_VAULTS` (8), for the Home feed's vault switcher and start screen. Disk entries keep their folder handle; browser entries keep their descriptor. Pure `addRecentVault` / `removeRecentVault` / `renameRecentBrowserVault` (carries a renamed browser vault's name into its entry, in place), plus `loadRecentVaults` / `saveRecentVaults` on the `idb.ts` store. Forgetting an entry never touches the vault's files.
- `opfs.ts` — Origin Private File System helpers for browser vaults (`hermes-vaults/…`): browser vault descriptors (`normalizeBrowserVaultName`: trimmed, required, ≤100 characters, for create and rename), workspace lookup / listing / deletion, persistent-storage request, usage estimate, backup-reminder check.

## Files

- `pins-model.ts` — The sidebar's pins, pure (pins are kept on this device, `atoms/pin-atoms.ts`): `PIN_PAGES`, `Pin` / `PinKind`, `pinKey()`, `PINS_MAX` (9); the entry rules (`parsePinItem`: one kind key — `note` (a `.md` vault path), `folder`, `tag` (normalised), `page` — and an optional single-emoji `icon`, `normalizePinIcon`), `listedPins` (recognised entries, first of each), `pinsDocument`, and the edits on a document of raw entries, each returning a new one or null when nothing changes: `addPins` (as many as fit), `pinsOverLimit`, `removePin`, `setPinIcon`, `movePin`, `remapPinPaths`, `forgetPinPaths`; `samePins`.
- `file-writer.ts` — `writeFileContent()`, the single write path for vault files. Uses `createWritable()` when the handle has it; otherwise (Safari before 26) sends the bytes to `app/workers/opfs-writer.worker.ts`, which writes through `createSyncAccessHandle()`.
- `git-read-client.ts` — Main-thread side of the read-only git reader (`app/workers/git-read.worker.ts`), started on first use: `getHead(vault)` (`{ available, commit, stamp }`) and `getHeadBlob(vault, commit, path)` (`{ status: ok | missing | binary | too-large | error, text? }`); identical in-flight requests are shared; runs inline where `Worker` is missing.
- `git-changes-client.ts` — Main-thread side of the Changes scan (`app/workers/git-changes.worker.ts`): `startChangesScan(vault, onProgress)` returns `{ result, cancel }` (`result` resolves `"cancelled"` after `cancel`); runs the scan inline where `Worker` is missing, and also when the worker errors or doesn't send `changes:started` within `START_TIMEOUT_MS` (4 s), so the page never waits on a worker that isn't running. A worker scan refused with `NotAllowedError` (the browser didn't extend the vault's permission to the worker) runs again inline, as do later scans.
- `git/` additionally holds the Changes page's scan: `git-changes-scan.ts` (`scanChanges`: HEAD's tree against the working files; `.git/index` stat matches skip reading, the rest are hashed 8 at a time, and a blob id is remembered by size and mtime so a rescan doesn't hash an unchanged file again), `git-index.ts` (index v2–4), `git-hash.ts` (`blobId`), `git-worktree.ts` (vault walk with `.gitignore` and `info/exclude` rules; a folder's files are read at once), `git-file-diff.ts` / `git-classify.ts` (per-file diff, binary and size rules), `git-line-diff.ts` (`lineChanges`, `gitDiff`), `git-changes-types.ts`, and `listTreeFiles` in `git-tree.ts`.
- `git/` — The reader itself, pure over `FileSystemDirectoryHandle` and never writing: `git-refs.ts` (HEAD → commit, with a change stamp), `git-repo.ts` (`.git` directory at the vault root, not sha256; only a missing `.git` means no repository, other failures throw), `git-objects.ts` (loose objects, LRU cache), `git-pack.ts` (pack `.idx` v2 lookup, entries inflated from `file.slice()` windows, OFS/REF deltas), `git-tree.ts` (`blobAtPath`), `git-read.ts` (the two reads the worker and client share: size and binary checks, one warning per file and commit), `git-fs.ts`, `git-test-utils.ts`.
- `text-grep-client.ts` — Main-thread side of the text-file grep (`app/workers/text-grep.worker.ts`), started on first use: `grepTextFiles(query, files, limit, onProgress, mode)` returns a stop function; a new search cancels the last. `mode: "regex"` arms a watchdog: 2.5 s without a report terminates the worker (a backtracking pattern can't be interrupted otherwise) and ends the search `stalled`, after one retry on a fresh worker when the search never got a report of its own (it was stuck behind an earlier one). Falls back to posting file text where handles can't go to a worker.
- `content-search-client.ts` — Main-thread side of the note-text index in the metadata worker: `indexNoteContent`, `removeNoteContent`, `remapNoteContent`, `markContentIndexed` / `needsContentIndex` (which notes the worker already has this session, by modified time), and `searchNoteContent` (resolves `null` when superseded or after 5 s). Holds no note text. No-ops without a worker.
- `vault-trash.ts` — The vault Trash's layout: `TRASH_DIR` (`.hermesmarkdown/trash`), `isTrashPath()`, slot names by deletion time (`trashSlotName` / `trashSlotDate`) and the 30-day expiry (`isTrashSlotExpired`). The Trash is skipped by indexing and export.
- `vault-data-dir.ts` — The vault's data folder, `VAULT_DATA_DIR` (`.hermesmarkdown`), which holds only the Trash and is created only when something is moved there; `isVaultDataPath()`. Pins and AI skills are the app's, never in the vault.
- `vault-archive.ts` — Whole-vault zip export / import (`fflate`; exports wrap entries in a vault-named folder, which import strips), folder copy, path sanitizing (no traversal, skips `.git` / `node_modules` and the Trash; Android storage-URI paths from a folder pick are rebuilt into folder-relative ones), and conflict-free naming (`name (1).md`).

## AI (client)

- `ai.ts` — Calls `/api/ai` for Claude and Gemini: chat (`callAIChat`), one-shot actions (`callAI`), note generation (`generateFileFromPrompt`), frontmatter suggestions, document fixes, model listing, and `testAIConnection`. The user's API key is sent with each request and never stored server-side. Gemini model listing calls Google directly from the browser.
- `ai-status.ts` — Reports AI action progress / success / error to the UI from non-React code.

## Legacy GitHub vaults

- `legacy-github-vaults.ts` — `migrateLegacyGitHubVaults()`, run once when the vault restores: copies each GitHub vault this device knew (last opened and recents) from its old OPFS folder into a new browser vault of the same name, rewrites its recents entry, then removes the old folder and IndexedDB keys. GitHub sync itself was removed; git happens outside the browser.
