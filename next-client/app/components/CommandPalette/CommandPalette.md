# CommandPalette

Description: Unified quick-open and command surface (`Ctrl/Cmd+K` or `Ctrl/Cmd+P` for files, `Ctrl/Cmd+Shift+K` or `Ctrl/Cmd+Shift+P` for commands; combos with Alt are left to other shortcuts). `Ctrl/Cmd+D` pins the selected row (a note goes into the vault's pins, kept on this device, which lead the empty list in pin order and are listed in the sidebar's Pinned section; a command into the palette's own pins); `Tab` / `Shift+Tab` move the selection. It also contributes its own **Show Files** command (`show-files`, `Ctrl/Cmd+Shift+E`), the only place it's registered (`useShowFiles`: on desktop shows the sidebar and focuses its Files tree where you are on any /editor route, coming to `/editor` from elsewhere; on mobile opens `/editor/files`), and **Search in Files…** (`search-notes`), which switches the open palette to the `/` note-text scope. On desktop it is a `.glass-panel` with `.glass-panel-soft` (a hairline in the text colour and a faint top highlight, not a white rim), 600 px wide, centred in the window at a fixed height (`min(520px, 100dvh − 2rem)`) so it doesn't jump as results change, and it scales in from 98 %. Its search field is the panel's top edge (`PALETTE_FIELD_CLASS`: full width, 17 px text, a hairline under it), which the toolbar's `SearchPill` and the feed's pill morph into. `CommandPaletteProvider` owns registration and `AppCommands` registers the app-wide commands (each command once; the editor adds only its own).

## Local State & Storage
- State: `atom_templates` (the `~` mode); `useCommandPalette()` context (isOpen, initialQuery, initialMenuId, open, openMenu, commands, register, createNote/setCreateNote); `menuPath`, the ids of the menus open (outermost first), resolved against the current commands on every render (`menuStack`). Atoms: `atom_palettePinnedItems`, `atom_recentFilePaths`, `atom_commandUseCounts`, `atom_recentCommandIds`, `atom_fileMetadata` and `atom_noteDisplayItems` (via `usePaletteFiles`), `atom_visibleTasks`, `atom_theme`, `atom_activeEditorView` (heading jumps), `atom_showHiddenFiles`, `atom_searchMarkdownOnly`, `atom_vaultTextFiles` (via `usePaletteFiles`), `atom_editorFontFamily`.
- Persistence: `localStorage` keys `palettePinnedItems` (max 5), `recentFilePaths`, `commandUseCounts`, `recentCommandIds`.
- Query prefixes: none = files, `#` tags, `!` tasks, `@` headings, `/` note text, `~` templates, `>` commands; the footer (`PaletteFooter`) shows each as a chip that enters it.
- Templates (`~`): `buildTemplateRows` over `atom_templates` (the vault's `_templates/` folder and its packs), matched by name, else by pack; the pack is shown on the right. Enter closes the palette and sends `hermes:insert-vault-template` with `detail.entry` to the active pane, which inserts it at the caret with no picker (`useTemplateNote` → `useVaultTemplateInsert(entry)`; its questions are still asked). `Ctrl/Cmd+Enter`, or Enter with no note open, makes a new note from it instead (`createNoteFromTemplate`: a name prompt, prefilled with the template's name). With no templates the mode says "No templates yet. Open Templates to add one or a pack." Ranking happens client-side in `command-search.ts`, except `/`, which runs in the metadata worker.
- Note text (`/`, also `Ctrl/Cmd+Shift+F`): `usePaletteContentSearch` debounces 60 ms (the index answers from memory) and calls `searchNoteContent(query, paths)` (`app/services/content-search-client.ts`); `paths` are the palette's `files` minus private ones, so `_` paths follow the hidden-files setting and "hidden" Privacy Mode notes are excluded too. Superseded responses are dropped and the previous rows stay until the new ones arrive. Matching: case-insensitive, every term must occur in the body (AND, plain substrings), frontmatter skipped, code included, 2-character minimum ("Type at least 2 characters to search file text."). Ranking (`app/workers/content-search.ts`): per line +100 per term, +500 for the whole phrase, +30 per term starting a word, +50 for headings; per note the best line, +1000 for the phrase anywhere, +200 for a term in the file name, +5 per occurrence (max 10). At most 3 rows per note, grouped by note. Each row (`PaletteRow`) shows the highlighted snippet, then `name:line` and the folder. Choosing one mirrors the file branch (close, `nextPaint()`, `openFile`, recents, `/editor` from elsewhere) and sets `atom_pendingScrollTarget` `{ path, line, column }`; `useScrollToPendingTarget` puts the caret on the first match and flashes the line, also when the note is already active. Pinning and the context menu don't apply. Private notes never match in any Privacy Mode (a masked row would still reveal that the note contains the phrase); the worker refuses them too. A muted footnote under the list reads "Indexing file text… N files left" while notes are still being indexed (the hook searches again every second meanwhile), or "Text search covers part of this vault (size limit reached)."; without a worker the scope says "Text search isn't available in this browser." The palette also mounts `useContentIndexSync()`, which drops deleted notes from the index.
- Read ahead: the highlighted file or text-search row's note is prefetched once the highlight rests on it ~100ms (`usePalettePrefetch`, `note-prefetch.ts`), so Enter opens it from memory when the file is unchanged. Opening the palette is timed for the dev-only PerfReadout (`startPerf` in `open` / `openMenu`, `finishPerfAfterPaint` once it's shown).
- Code files: `usePaletteFiles` appends the vault's text files (`atom_vaultTextFiles`; `isText: true`, by name with extension, never private, no tags), so Quick Open finds and opens them; they're left out of the note-text `paths`. `usePaletteContentSearch` calls `grepTextFiles` (`app/services/text-grep-client.ts`) for these files after a 100 ms debounce unless `atom_searchMarkdownOnly` is enabled. The text-grep worker reads each file (from its cache after the first search) and streams ranked hits, which follow the notes' rows; the footnote reads "Searching files… N of M" until it's done, and the empty state waits for it. Both result sets keep their previous rows until the newer search answers.
- Regex (`atom_searchRegex`, remembered): in the `/` scope the footer shows a **Regex** chip (`.*` key cap, lit while on; `PaletteFooter`'s `regex` prop) and `Alt+R` toggles it (matched on `event.code`, as Option+R types ® on a Mac). With it on, the note-text index isn't asked: every listed public note (`isNote: true`, frontmatter skipped, board JSON blanked) and every readable text file goes to `grepTextFiles(…, "regex")`, unless Search Markdown Files Only is enabled. Case-insensitive, `^`/`$` per line (`app/workers/regex-search.ts`). An invalid pattern shows "Not a valid regular expression yet."; a pattern that runs too long (the worker is shut down after 2.5 s without a report) shows the footnote "Search stopped: this pattern takes too long. Try a simpler one.".
- Replace…: in the `/` scope with a query typed, the footer shows a **Replace…** chip (`⇄` key cap; `PaletteFooter`'s `replace` prop). It closes the palette and opens `/editor/replace?find=<query>` (plus `&regex=1` when Regex is on, `editorReplaceHref`). The **Replace in Files…** command (`replace-in-files`, in `AppCommands.tsx`) opens the page empty.
- Layout: the search field (`PaletteSearchBar`) runs the panel's width; inside a menu a Back chevron leads it. Rows (`PaletteRow`) have a leading icon and key-cap shortcuts; in the default list a hairline sets the notes apart from the menu. The footer (`PaletteFooter`) is the modes' legend, chips that enter each mode, and the version; nothing in it repeats the list (Settings and the theme are commands).
- Search anchor morph: when an element with `data-palette-anchor` is on screen (the toolbar's or a page's `SearchPill`), `open`/`close` run inside a View Transition. The anchor and the palette's search field share the `palette-search` transition name (`PALETTE_SEARCH_TRANSITION`), so one morphs into the other; timings live in `globals.scss`. The transition waits for the palette field (`[data-palette-field]`) to mount or unmount (it renders through a Portal), and while `isMorphing` (set for the whole of a morphed open, not just the transition, so the fade-in never replays afterwards) the panel skips its own enter/exit animations and exit delay so the morph stays visible. Without View Transitions support, or with reduced motion, the palette just opens. With a create handler registered, the placeholder reads "Search or create a note…" (`SEARCH_OR_CREATE_PLACEHOLDER`), matching the pill.
- Default list (empty query): pinned rows and up to five recent notes, then the top-level menu: the actions (`TOP_LEVEL_ACTIONS`: Search in Files…, Ask AI, New File, Insert template…, Toggle Focus Mode), then the pages (`TOP_LEVEL_PAGES`: Open Tasks, Open Templates, Open Settings, Open Documentation). Hairlines set the three groups apart (`rowGroup`: notes, actions, commands with `opens`); an empty `>` list sorts pages after actions and is set apart the same way. A command with `opens` is marked at the end of its row: an arrow for another page of the app (`"page"`), the external mark for a new browser tab (`"tab"`, also "(opens in a new tab)" in its accessible name). Open Documentation is the one tab: it opens `/documentation` in a new tab, so the note stays where it is. A command that isn't registered (no vault, AI Features off) or is pinned is skipped; the notes give way so the menu always fits in `MAX_VISIBLE_ROWS`. The same order leads an empty `>` list, after the most-used commands.
- Menus: a command with `subcommands` opens in place instead of running (`markUsed` still counts it). Its rows (`buildMenuRows`) are its list for an empty query, with each row's `description` as context; a query searches the list and the actions inside its own menus. The field's placeholder names the path (`Ask or Edit with AI › Improve Writing…`); `Backspace` in an empty field or the **Back** button beside it goes up a level, the `>` button leaves for command mode, Escape closes. Prefixes aren't parsed inside a menu. `openMenu(id)` opens the palette straight into a menu (`Ctrl/Cmd+J` → `ai-menu`).
- Create row: when the file query has no note with exactly that title (case-insensitive), the last row is `Create "<query>"`. It calls the `createNote` handler that the editor registers through `setCreateNote` while a vault is open; the handler saves a new note titled with the query and opens it.
- Private notes (`private: true` or a `private` tag): `usePaletteFiles` (`use-palette-files.ts`) builds the file list through `atom_noteDisplayItems`, so each `FileResult` has `isPrivate` (a `PrivateBadge` lock follows the row label, and the accessible name adds "(private)"), and Privacy Mode "Hide from lists" (`hidden`) drops private notes from search, `#tag`, recent and pinned rows. Stored pins and recents are untouched, so they come back when the mode changes. The Create row checks `existingFiles` (ignoring Privacy Mode), so it never offers a hidden note's existing title. `!` tasks come from `atom_visibleTasks` through `buildTaskRows`: a masked task shows `MASKED_TEXT` with a lock and `path:line`, only for the empty query, and never matches by text; in "hidden" it's omitted.
- A command with `closeFirst` (Insert template…, Save as template…, the `Insert: …` commands) closes the palette and waits a paint before it runs, so its dialog or its change to the note shows at once with the focus back in the editor.
- Choosing a file closes the palette first (after `nextPaint()`), then calls `openFile`; the editor's `LoadingBar` covers the read and re-render. Long-running commands keep the palette open and show a spinner on their row (`aria-busy`).

## Dependencies
- Core: `OverlayPanel`, `Button`, `useFileSystem`, `@codemirror/view` (for heading jumps), `react-icons`.
- Content search: `usePaletteContentSearch`, `useContentIndexSync`, `PaletteRow`, `atom_pendingScrollTarget`.
- Zero-Cloud: No network or telemetry side effects. All search runs in memory; note-text search runs in the metadata worker.

## Quick Usage
```tsx
import { useRegisterCommand } from "@/app/components/CommandPalette/CommandPaletteContext";

useRegisterCommand({ id: "doc.export", label: "Export", category: "Document", action: exportDoc });
```

## Props Overview
| Prop | Type | Default | Description |
|---|---|---|---|
| (none) |  |  | `CommandPalette`/`AppCommands` take no props |
| children | `ReactNode` |  | `CommandPaletteProvider` |

`Command` fields: `id` (stable, unique), `label`, `action`, `category?`, `shortcut?`, `description?`, `keywords?`, `disabledReason?`, `danger?`, `closeOnRun?`, `closeFirst?`, `opens?` (`"page"` / `"tab"`: it leaves the note), `subcommands?` (a menu).
